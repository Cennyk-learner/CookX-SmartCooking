# Android 体验使用说明

## 安装与首次打开

安装签名 APK。桌面名称为 **CookX 体验版**，包名 `com.smartcooking.app.showcase`，版本 2.2.4（24）。它与正式版 `com.smartcooking.app` 可以共存，也可覆盖更新同证书的旧体验版并保留本机数据。

打开后直接进入「林小厨」的厨房，无需注册或登录。已有库存、菜谱、家庭、采购、社区、成长记录和七日菜单，操作会在本机保存。初始记录是体验示例，不是实际用户使用记录。

2.2.4 修复识别结果确认入库时误报「操作凭证不能用于不同内容」的问题，同时修复共用请求流程中的手动添加、编辑和删除。覆盖安装后，旧版错误的身份检查凭证会自动清理，已保存的库存、识别草稿和有效操作回执保留。打开原识别草稿核对后重新确认即可，无需重置厨房或更换在线服务配置。重复提交同一笔成功操作仍只记一次；同一凭证提交不同内容仍会被拒绝。

如果手机已安装旧的同包名体验版，通常可覆盖更新。遇到签名不一致时，先备份需要保留的内容，再处理旧安装；不要为了安装而误删正式版。该版本关闭系统自动备份，密钥不随备份迁移。

## 内置在线服务与更换配置

内置服务的安装包打开后即可联网使用 AI 菜谱和图片识别，不需要填写 Key 或部署电脑。**AI 菜谱由 Kimi K2.6 生成；照片识别、语音指令及在线播报由 Qwen 处理。**两项服务使用独立加密密钥，不会混用接口。「我的 → 体验管理」分别显示两项服务；Qwen 的「检测连接」只检测百炼，不调用 Kimi 生成。

在 **AI 菜谱** 输入「做两人份番茄炒蛋」，成功后显示「Kimi K2.6 已生成」及完整菜谱，可继续输入「改成少油、三人份」，也可收藏、复刻或开始烹饪。历史菜谱保存在本机，再次打开不重复调用模型。每次生成关闭思考模式、最多输出 2000 token，不自动重试；额度与实际费用以 Kimi 账户为准。网络或额度异常会说明原因并打开明确标注的内置菜谱。

手机「更换服务配置」用于更换 **Qwen** 的 Key 与匹配接口。如果之前手动保存过 Qwen 配置，会优先保留；「恢复内置服务」切回默认配置。更换内置 Kimi Key 需要重新构建签名安装包。未内置 Qwen 服务的构建可按下面步骤配置：

1. 在手机或电脑浏览器打开[阿里云官方获取 API Key 教程](https://help.aliyun.com/zh/model-studio/get-api-key)，进入百炼控制台。
2. 登录阿里云账号，按控制台要求开通服务，选择**华北 2（北京）**地域并创建 API Key。API 调用按账号额度和用量计费，以控制台显示为准。
3. 手机打开 **我的 → 体验管理 → 更换服务配置**，粘贴 Key 及同业务空间的 `/compatible-mode/v1` HTTPS 地址，点击 **保存并检测连接**。普通北京共享接口为 `https://dashscope.aliyuncs.com/compatible-mode/v1`，业务空间 Key 可使用控制台给出的专属地址。该操作发送一个很短的文本请求核对文本模型权限。
4. 显示「Qwen 已连接」后，到冰箱页验证识别；此检测不代表 Kimi 菜谱已验证。
5. 到 **冰箱 → 识别食材 → 拍照识别/从相册选择**，选择真实食材照片，核对识别清单后再入库。连接检测不等于照片识别已经验证。
6. 烹饪时在工具中尝试「在线播报」。它也使用同一把 Key，但需有对应语音模型权限。

手机直接使用以下接口与模型，无需部署电脑后端：

| 用途 | 模型 / 服务 |
| --- | --- |
| 菜谱生成 | `kimi-k2.6`，Kimi 官方 `https://api.moonshot.cn/v1` 接口 |
| 照片识别 | `qwen3-vl-plus`，同地域多模态 Chat Completions 接口 |
| 在线播报 | `qwen3-tts-flash`，官方北京共享域名的 MultiModal Generation 接口 |
| 语音指令识别 | `qwen3-asr-flash`，配置的北京地域 Chat Completions 接口 |

参考：[Kimi K2.6](https://platform.kimi.com/docs/guide/kimi-k2-6-quickstart)、[视觉接口](https://help.aliyun.com/zh/model-studio/vision/)、[在线语音接口](https://help.aliyun.com/zh/model-studio/qwen-tts-api)。模型权限、可用性与额度以对应服务控制台为准。

手动填写的 Key 用 Android Keystore 加密后保存在这台手机；仓库不保存真实 Key。内置服务的 Key 以 AES-GCM 加密内容随安装包提供，重新安装仍可使用内置配置。可在体验管理「停用在线服务」；此设置重启后仍有效，不影响本地业务。

仅主动发起在线操作时发送必要内容：菜谱请求包含需求、可用库存和当前烹饪步骤/温度状态；识别发送选定照片；在线播报发送当前步骤文本；点击语音指令麦克风后向百炼发送最长 8 秒的短录音，录音仅在内存中处理，不写入历史或持久文件。用户与家庭数据库不上传到自建服务。语音识别接口参考[阿里云 Qwen-ASR 文档](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)。

## 建议体验路线

1. **首页 → 冰箱**：查看预置库存和临期食材；打开通知可定位到具体批次，修改或删除后提醒随之更新。
2. **识别食材**：有网络时拍真实照片；无网络时选择「体验示例食材」，页面明确显示「非照片识别结果」。核对数量、日期和储存方式后确认入库。可保留草稿或明确放弃。
3. **AI 菜谱 / 菜谱库**：在线生成一份菜谱，或打开内置菜谱。首页最近菜谱打开原内容，不会重新请求生成。收藏与复刻保存独立副本。
4. **开始指导**：进入分步烹饪，点击「语音指令」麦克风并允许录音，等显示「录音已就绪」及输入音量条后，说「下一步」「请切换到下一步」或「返回上一步」。说完稍停会自动识别，也可点「说完了」提交；「取消」或 × 放弃本次录音。有网络与可用模型配置时直接调用百炼，无需安装系统识别服务或携带电脑；联网失败后，如有系统识别服务会提示再说一次。「不要下一步」和冲突指令不会自动执行。文字输入与步骤按钮仍可使用。系统播报需中文 TTS 语音包，没有语音包可使用「在线播报」。
5. **连接 CookX Sense**：开启手机蓝牙，按原有方式配对 JDY-31，在厨房设备入口选择设备。等待连续有效测量后展示温度与趋势。不要把探头温度当成食物中心温度。
6. **温度备用演示**：没有硬件时，在厨房温度详情打开「仿真回放」。界面标明「物理仿真回放 · 非设备实测」，不冒充现场采集。连接真实硬件前停止回放。
7. **完成烹饪**：选择实际使用的库存批次与数量，再确认完成并扣减。失败时保留原凭证核对/重试；也可明确选择「仅记录完成，不扣库存」。完成后可选择添加剩余熟食记录。
8. **七日菜单**：点击「接受预设并生成菜单」，查看 2 人、7 天午晚餐的组合。保存后逐菜复刻进入备菜，或前往共同采购选择该菜单生成需求。
9. **共同采购**：认领 → 标记购买 → 填写实际收到的数量/单位/储存信息 → 入库。不同单位不自动换算。
10. **一起晒菜 / 厨艺成长**：发布本机作品、点赞评论或收藏作品；查看新增烹饪记录与预置示例记录。

## 断网与恢复

**语音兼容处理**：录音启动完成并收到第一帧后才提示就绪。低音量不会再被旧的固定门槛直接拒绝；纯静音或直流输入不会上传。普通采集失败时最多切换一次麦克风模式，出现「兼容录音已就绪」后需重新说一句。系统明确暂停麦克风时直接说明原因，不循环切换。录音最长每次 8 秒；准备或识别期间无需说话。取消和切后台会终止本次语音，返回后重新点击麦克风。系统识别是否离线可用取决于手机服务。

**智能推荐评分**：冰箱内打开「用这些食材能做什么」，点击获取或重新推荐。总分为 0～100，展开「评分依据」可查看食材匹配、临期利用、偏好、减少浪费等分项及有效权重。预算、难度和营养仅在提供对应目标与可靠数据时参与，不生成虚构价格或营养。库存和条件变化后重新计算；默认按综合分排序，开启且通过验证的偏好模型可另行重排。

- 冰箱、批次写入、菜谱库、菜单、本机家庭/社区、计时、烹饪记录均不需要电脑或网络。
- AI 请求无法完成时，界面说明打开的是**内置菜谱**，不会声称本次 AI 已生成。照片识别失败时提供手动录入或示例入口，不虚构照片结果。
- 系统语音是否离线可用取决于手机已安装的中文语音包和识别服务。文字指令与步骤按钮始终保留。
- API Key 无效/无权限：检查是否北京地域 Key，模型服务是否开通。额度不足或请求受限：查看百炼控制台。超时：换手机网络后重试。
- 每轮体验前可用 **我的 → 体验管理 → 恢复初始内容** 重置厨房。确认后清除后续库存、作品、草稿和烹饪进度；API Key 保留。
- 不要在正在保存库存、在线生成或连接设备的途中重置。

## 出发前在实际手机核对

充足电量；开启通知、麦克风和所需蓝牙权限；准备手机流量；确认真实 AI 菜谱、真实照片识别、中文语音和 JDY-31 连续读数各成功一次；随后关闭网络再走一次内置菜谱与库存流程。即使有本地备用入口，出发前仍需核对实际手机与硬件。
